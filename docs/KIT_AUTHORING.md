# Writing champion kits

A **kit** (`src/kits/champions/<ChampionId>.ts`) tells the simulator how a champion's abilities turn
into damage: which game formula is dealt as which damage type, how many times, when, and with which
side effects (buffs, debuffs, marks, crowd control). Champions without a kit use an
auto-generated one (`src/engine/autokit.ts`) that is only a rough guess.

## Golden rules

1. **Numbers come from the game, never from you.** Amounts are expressions over the game's own
   formulas: `calc.TotalDamage`, `dv.BaseDamage`, `P.calc.BleedDamagePerStack`… These are the exact
   values the client shows in tooltips for patch 16.20. Only hard-code *mechanics* that are not in the
   data (a tick interval, "two extra fox-fires"), and comment where they come from.
2. **One target, a champion.** Model what happens to a single enemy champion standing in the ability.
   Ignore minion/monster damage, healing and shields on yourself.
3. **Default = typical full cast.** Components that normally hit are on by default. Conditional extras
   ("if the target is isolated", "sweet spot", "max charge") are `optional: true` or a `variant`.
4. **Write down assumptions** in `notes` (kit-level or ability-level). Users and AI agents read them.
5. **Check your work**: `node scripts/check-kits.ts <Id> --verbose` must pass, and a simulated combo
   must match the rendered tooltip numbers (see "Workflow").

## Workflow

```bash
node scripts/inspect-champion.ts Garen 11 --all-spells     # data, formulas, rendered tooltips
# write src/kits/champions/Garen.ts
node scripts/check-kits.ts Garen --verbose                 # expressions resolve, values sane
node src/cli/main.ts champion Garen -l 11                  # per-ability component values
node src/cli/main.ts simulate -c Garen -l 11 --combo "Q AA E R" --target hp=2000,armor=80,mr=50 --events
```

`inspect-champion` prints, for every spell of the champion: the raw tooltip, the tooltip rendered with
current numbers, every data value per rank (`dv`) and every calculation (`calc`) as a readable formula
plus its value at the inspected level/rank. **Compare your component values with the rendered tooltip**
— they should match exactly (the rendered tooltip is what the player sees in game).

For hidden mechanics (hit counts, how a passive stacks, whether something can crit, timings) check the
wiki page `https://wiki.leagueoflegends.com/en-us/<Champion_Name>` (the raw page text is at
`?action=raw`). The wiki can lag the patch: **numbers always come from the game data**; use the wiki
only for behaviour.

Kit files are loaded automatically in Node (CLI/MCP/scripts). The web build uses `src/kits/all.ts`,
which is regenerated by `node scripts/gen-kit-index.ts` — don't edit it by hand.

## File shape

```ts
import type { ChampionKit } from '../../engine/kit-types.ts';

const kit: ChampionKit = {
  id: 'Garen',              // champion id exactly as in data (e.g. 'MonkeyKing', 'KSante', 'Belveth')
  status: 'curated',        // 'verified' only after checking numbers in game / against a second source
  notes: ['…assumptions that affect results…'],
  options: [ /* champion parameters, e.g. stacks */ ],
  abilities: { P: {…}, Q: {…}, W: {…}, E: {…}, R: {…} },
  attack: { /* passive on-hits, every-Nth-attack procs, crit modifiers */ },
  marks: [ /* stacking target marks (bleeds, 3-hit passives) */ ],
  stats: (ctx) => ({ /* passive stat bonuses */ }),
};
export default kit;
```

Types are in `src/engine/kit-types.ts` (read it — every field is documented).

## Expressions

Amounts, hit counts, durations etc. are expression strings (or plain numbers):

| Name | Meaning |
|---|---|
| `calc.X`, `dv.X`, `rank`, `cooldown` | This ability's spell: calculation X evaluated at the current rank/level/stats; data value X at the current rank |
| `Q.calc.X`, `P.dv.X`, `R.rank` | Another slot's spell |
| `spell['ScriptName'].calc.X` | Any spell of the champion by script name (forms, sub-spells) |
| `ad bonusAd baseAd ap maxHp bonusHp baseHp hp armor bonusArmor mr bonusMr as bonusAs critChance critDamage lethality ms bonusMs mana bonusMana range ah level ranged` | Your stats (`bonusAs` is a fraction, `critDamage` e.g. 2.0) |
| `target.maxHp target.hp target.missingHp target.hpPct target.missingHpPct target.bonusHp target.baseHp target.armor target.mr target.bonusArmor target.bonusMr` | The target (current HP updates hit by hit) |
| `opt.name` | A kit option (declare it in `options`) |
| `target.immobilized target.slowed target.impaired target.cced` | 1 if the target currently has that crowd control from you |
| `recast` | 1-based index of the cast within a recast chain |
| `charge` | Seconds the slot's cast was held to charge (`charge` abilities; their default before a cast) |
| `stacks.markId` | Current stacks of a kit mark; `buff.id` / `debuff.id` are 1 while active (or the stack count) |
| `hit`, `hits` | Index (0-based) and count of the current hit in a multi-hit component |
| `time`, `combatTime` | Seconds since combo start / since entering combat |

Functions: `min max abs floor ceil round sqrt clamp(x,lo,hi) lerp(a,b,t)`, operators `+ - * / % ^`,
comparisons, `&& || !` and `cond ? a : b`. Names that aren't identifiers use brackets:
`calc['{c61fdd37}']`.

### Units — the #1 source of mistakes

* A calc shown "as %" (inspect prints `[shown as %]`) returns a **fraction** (0.04 = 4%).
* A tooltip ref written `@X*100@%` means X is a **fraction**.
* A calc/dv shown in the tooltip as `@X@%` *without* `*100` and without `[shown as %]` is in
  **percent units** (e.g. `TotalADRatio = 100/110/120`): divide by 100.
* `% max/current/missing Health` → multiply the fraction by `target.maxHp` / `target.hp` /
  `target.missingHp` (or `maxHp` etc. for *your* health).
* Check the inspect output: it prints every calc's evaluated value; the rendered tooltip shows what the
  client displays. Your component's value must equal the tooltip number (for % health damage: the
  fraction × the health).

## Components

```ts
{ id: 'out', label: 'Orb of Deception (out)', type: 'magic', amount: 'calc.TotalDamage', aoe: true, delay: 0.3 }
```

**Naming hits.** A hit's `label` names it on its own, wherever it's shown beside its source (the
ability, passive or mark) or without it: the ability's own damage by the ability's name, a part of it
by that name with the part in parentheses (`Super Scorcher Breath (burn)`, `Super Scorcher Breath
(execute)`, `Hemorrhage (bleed)`), and a hit with a name of its own in the game by that name (Gold
Card, Tailwind, Eternal Hunger). Never a bare word like Execute, Bleed or Burn, a shortened source
name (Orb for Orb of Deception) or `Blaze burn` for `Blaze (burn)`: the HP bar's hover card names a
part that way when its hits are all one part of their source.

| Field | Use |
|---|---|
| `type` | `physical`, `magic`, `true`, or `adaptive` |
| `amount` | raw damage of **one** hit |
| `hits`, `interval`, `delay` | number of hits in a default cast, seconds between hits, seconds after the cast time (a wait the wiki documents: arming, a heft, a detonation) |
| `travel` | seconds a hit flies after it's fired: `true` to the target at its missile's speed (`reach / missileSpeed`, from the data), or an expression (`'reach / 2200'`) |
| `maxHits` | the most hits a longer duration or a step's count fires (default `hits`) |
| `optional: true` | off unless the combo enables it (`Q+bonus` / `enable: ['bonus']`) |
| `aoe`, `dot`, `pet` | damage tags (affect items/runes: Deathfire Touch duration, Aery, etc.) |
| `canCrit`, `critMultiplier` | can crit (expected-value in default mode); custom multiplier e.g. `'1 + 0.3 * (critDamage - 1)'` |
| `attack: true` | this hit *is* a basic attack (applies on-hit, counts for PTA/Conqueror as an attack, can crit) |
| `onHit: true` | ability damage that also applies on-hit effects (Fizz Q): Spellblade, Energized procs, Kraken, BotRK… |
| `onAttack: true` | with `onHit`/`attack`: also triggers on-attack effects (Ezreal Q, Smolder Q): Guinsoo's and Lethal Tempo stacks, Energize charges, Navori, Yun Tal, Hail of Blades |
| `areaOnHit: true` | on-hit applied by an area effect, which Press the Attack ignores (Katarina daggers, Master Yi Q) |
| `proc: true` | proc damage (the wiki's "spell effects: proc", "deals proc damage"; Lux's Illumination, Kog'Maw W's on-hit): no spell effects (Liandry's, Luden's, Comet), no rune triggers (Electrocute, Dark Harvest, Conqueror, Cheap Shot), doesn't apply or detonate the kit's marks |
| `noProc: true` | not ability damage, but not proc damage either (the wiki's "default damage"): no spell effects, still triggers runes. Also an ability's attack that works like a regular attack (Jayce W, Rengar Q), and an `attack: true` hit that is basic damage only (Zeri's Burst Fire) |
| `execute: true` | a literal execute (Pyke R, Urgot's Mercy): `amount` is the health it executes below, its line. It kills a target at or under the line as it lands, and so sets off nothing at all; above it, it deals nothing. Like any damage counted past the kill, it counts for its full value (the line) as true damage with no amps or mitigation, also when the target's health is already past 0. Only the largest execute counts, whenever it lands (the target dies once). From a hook, `sim.deal` with `flags.execute` and the line as `amount`, every time it's checked, without comparing the health yourself: the results mark the line on the health bar whether it's reached or not (`executeLines`), and Settings can turn executes off. One a hook asks for, or one of a cast's hits landing together, lands after the rest of that instant's damage: the hits, then what they set off, then the execute, which checks the health they left |
| `spell: true` | spell damage where the hit otherwise isn't: a passive's part of an attack (Diana's Moonsilver Blade), which is default damage unless marked |
| `slot` | in the kit's `attack`: the basic ability whose passive deals the hit (Ekko W's Parallel Convergence, Teemo's Toxic Shot), shown under that ability, its `calc.`/`dv.` that ability's |
| `min`, `max` | clamp the amount (e.g. Darius R cap) |
| `condition`, `note` | short text shown in UIs |

Hit counts default to 1. For "deals X per second for N seconds" use `hits: N`, `interval: 1`, `dot: true`
(or the real tick rate if known). If the number of hits depends on stats, use an expression
(Garen E: `'dv.NumTicks + floor(bonusAs / dv.ASPerTick)'`).

A cast's hits landing at the same moment (the same delay) are dealt together in component order, then
what they set off: the on-hit effects of its `onHit`/`attack` hits and items', runes' and Ignite's procs
(Smolder Q, its Dragon Practice bonus, then Spellblade). A kit hook's damage is dealt when the hook
deals it, except an execute, which comes last (see `execute: true`).

When the player chooses how long an ability lasts (a channel they can end early: Smolder E,
Katarina R; a toggle: Karthus E), mark it `variableDuration: true`. A combo step then sets its
seconds after its cast time (`E{0.5s}`, the web UI's field on the step): its repeating hits land
within them and its lockout ends with them. It lasts its lockout by default, else as long as its
hits take; give hits that can go on longer a `maxHits`, and a channel that can a `maxDuration`
(Aurelion Sol Q). It lasts at least until its first hit is fired, or `minDuration` when it can only
be ended later (a recast after 0.5s: Urgot W). Hits fired before it ends still land (a missile's
`travel` comes after its firing, Xerath R), and a hit at the end of a full channel
(Fiddlesticks W's last tick) doesn't. Don't mark what the player can't end (burns, fixed zones),
unless it goes with the target as it moves, which nothing in the simulator does (Yunara W's bead
follows a target running away): the step's seconds are then how long it stays on the target, the
default a target standing still, the most what the target could make it.

When the player chooses how many hits it fires rather than for how long (Xerath R's and Jhin R's
shots), mark it `variableCount: 'shots'` instead: a step sets the count (`R{3}`, at least 1), the
first that many of its hits in the order they're fired (Jhin's 4th shot, its own component, is
always the last), and its lockout ends when the last of them is fired.

An ability held to charge (Sion Q, Varus Q) takes `charge: { default, min, max }`: the step's seconds
are the hold (usually the full charge by default; `min` is the earliest release, `max` the longest
hold), which `castTime`, amounts and `cc` read as `charge`, e.g. `castTime: 'charge'` and
`amount: 'lerp(calc.MinDamage, calc.MaxDamage, min(1, charge / 1.25))'`. When the champion acts while
it grows (Gragas Q, Janna Q), leave the cast time and delay the hit instead (`delay: '0.5 + charge'`).
Use it in place of quick/tap variants.

## Abilities

```ts
Q: {
  components: [...],
  variants: { empowered: { label: 'empowered', components: [...] } },   // combo: Q:empowered
  defaultVariant: undefined,
  buff:   { id, label, duration, stats: { attackSpeed: 'dv.AS' }, empowerAttacks: {...}, onHit: [...], damageAmp },
  debuff: { id, label, duration, armorReduction, mrReduction, damageTakenAmp, afterHits, consume, detonate },
  cc: [{ kind: 'immobilize', duration: 'dv.StunDuration' }],   // immobilize | slow | impair
  dash: true, resetsAttack: true, recasts: 3, recastDelay: 1, noTarget: true, castTime: 0.25,
  notes: ['…'],
}
```

* **CC matters**: Aftershock, Cheap Shot, Glacial, Imperial Mandate react to it. Mark stuns, roots,
  charms, knock-ups, fears, taunts, suppressions and sleeps as `immobilize`; slows as `slow`;
  silences/blinds/grounds/polymorph/disarm as `impair`. The tooltip's `<status>` tags tell you.
* **Dashes/blinks**: `dash: true` (Sudden Impact).
* **Attack resets**: `resetsAttack: true` (Hail of Blades, attack timing).
* **Cooldowns** come from the data automatically.

### Patterns

**Empowered next attack** (Garen Q, Darius W, Nasus Q, Jax W…):
```ts
Q: { resetsAttack: true, buff: { id: 'garenQ', label: 'Decisive Strike', duration: 'dv.AttackWindow',
     empowerAttacks: { count: 1, replaceBase: true, components: [{ id: 'strike', label: 'Decisive Strike', type: 'physical', amount: 'Q.calc.TotalDamage' }] } } },
```
`replaceBase: true` when the tooltip's damage *is* the attack's damage ("his next attack deals X");
leave it false when it's *bonus* damage ("deals X bonus damage"). Write combos as `Q AA`. Either way
the results show the attack's normal damage as the attack's and only the extra as the ability's: a
replaced attack is recorded in two parts, the attack's out of its first hits (`AttackInfo.replacedBy`, hooks add theirs: Galio's
passive), unless someone else attacks instead (`otherAttacker: true`, Azir's soldiers). What
`empowerAttacks` adds is flagged `empowered` (a hook's own hits set it), and the health bar names
the attack after it.
An attack the components replace is the ability's spell damage as well as basic damage (the wiki's
"basic damage, but also tagged as spell damage"), unless `noProc`. When the wiki says the same of an
attack that keeps its own damage (Wukong Q, Kayle E, Vayne Q), set `empowerAttacks.spell: true`.
Inside buffs/marks/attack hooks, refer to formulas with an explicit slot (`Q.calc.X`).

**Buff with on-hit damage while active** (Kog'Maw W, Twitch/Vayne steroids, Varus):
`buff: { id, label, duration, stats: { attackSpeed: 'dv.AS' }, onHit: [{ id, label, type: 'magic', amount: 'W.dv.PctMaxHp * target.maxHp' }] }`.
`stats` keys are StatMods keys: `ad ap attackSpeed critChance lethality armor mr hp msPercent abilityHaste …`
(fractions for percentages).

**Passive on-hit / every N-th attack** (`kit.attack`):
```ts
attack: { onHit: [...], everyNth: { n: 3, label: 'Silver Bolts', components: [...] } }
```

**Stacking mark on the target** (Darius bleed, Vayne W, Brand P, Kai'Sa P, Ekko P):
```ts
marks: [{ id: 'hemorrhage', label: 'Hemorrhage', maxStacks: 'P.dv.MaxStacks', duration: 'P.dv.BleedDuration',
  appliedBy: ['attack', 'Q', 'W'],          // 'attack' | 'ability' | 'onhit' | slots
  dot: { interval: 1.25, components: [{ id: 'bleed', label: 'Hemorrhage (bleed)', type: 'physical', amount: 'P.calc.BleedDamagePerStack / 4 * stacks.hemorrhage', dot: true }] },
  atMax: { components: [...], consume: true, cooldown: 'P.dv.Cooldown', buff: {...} } }]
```
Use `stacks.<id>` in any expression (Darius R). One stack per cast by default (`oncePerCast`).

**Mark detonated by a later hit** (Lux P): put a `debuff` with `consume: { by: ['attack','R'], components }`
on every ability that applies it. A hit from a different cast detonates it.

**Delayed detonation storing damage** (Zed R): `debuff.detonate: { components, storeFraction, storeType }`.

**Execute / missing-health scaling**: `'calc.ExecuteThreshold'` with `execute: true` (a literal execute;
the engine checks the target's health), or use `target.hp`, `target.missingHpPct`:
`'calc.Base * (1 + dv.Amp * target.missingHpPct)'`.

**Forms and alternate spells** (Jayce, Nidalee, Elise, Gnar, Kayle R…): variants with `spell: 'ScriptName'`
pointing at the other form's spell (inspect with `--all-spells` lists unslotted spells), e.g.
`Q: { variants: { cannon: { label: 'cannon', spell: 'JayceShockBlast', components: [...] } } }`.
A variant the game casts by itself in a state, not one the player picks, sets `when`, an expression:
the step names the ability and casts it while that holds (Yunara's `when: 'buff.yunaraR'` on W and E,
a buff her R applies for it).

**Stacking champion stats** (Nasus Q stacks, Veigar AP, Senna, Smolder, Cho'Gath R, Sion, Kindred,
Thresh, Swain): declare an option and use it:
```ts
options: [{ key: 'stacks', label: 'Siphoning Strike stacks', default: 100, min: 0, max: 2000 }],
abilities: { Q: { buff: { … amount: 'Q.calc.BaseDamage + opt.stacks' } } },
stats: ({ opt }) => ({ ap: opt.stacks }),         // e.g. Veigar
```
Game formulas that read buff counters (`stacks({abcd1234})` in inspect output) can be fed with
`buffStacks: { '{abcd1234}': 'opt.stacks' }`.

**Passive stat bonuses** (`stats`): `stats: ({ level, opt, ranks, evalExpr }) => ({ armorPenPercent: [evalExpr('E.dv.ArmorPen') / 100] })`.
Percent penetration values are arrays (they multiply).

**Attack speed caps**: `attackSpeedCap` raises the cap (Bel'Veth, Hail of Blades);
`attackSpeedCapLimit` lowers it, and then nothing raises it but `attackSpeedPastCap`, bonus attack
speed that raises the cap by as much as it adds (Zeri: `attackSpeedCapLimit: 1.5` in `stats`, her
Overcharged buff's `stats: { attackSpeedPastCap: 'dv.BaseASPercent' }`; Kennen's Lightning Rush).
The conversion source `bonusAttackSpeedOverCap` is the bonus attack speed past the cap, without what
raises it (Zeri's AD from it, like Yasuo's `critChanceOverCap`).

**Crit modifiers** (Yasuo/Yone ×0.95, Jhin ×0.75, Senna ×0.8): `attack: { critMultiplier: 'critDamage * 0.95' }`
(look up the passive's data value instead of hard-coding when it exists).

**Abilities that are attacks** (Yasuo Q, Fiora Q's crit?): `canCrit: true`, `onHit: true` on the
component; use `attack: true` only if it fully counts as a basic attack. An `attack: true` hit crits
by its own `canCrit` (default yes), not by `kit.attack.canCrit`, which is the champion's basic
attacks'. A cast that counts as an ability cast except for Spellblade takes `noSpellblade: true`, and
one whose cooldown is an attack timer (`1 / as`) `attackTimer: true`: ability haste and Navori don't
shorten it, and attack resets reset it (Zeri's Burst Fire, reset by Spark Surge). An attack fired as
several hits that apply on-hit effects once (Burst Fire's rounds: "to the first enemy hit") is one
`attack: true` component with `hits`, `interval` and `onHitOnce: true`: the first hit to land is the
attack, the rest deal its basic damage only.

**Attacks that are abilities** (Zeri's right-click, "treated as Abilities"): `attack: { ability: true }`
keeps the attack's timing (attack timer, windup, range) but casts it as an ability: on-cast effects
trigger as it hits (it arms Spellblade then), all it deals is spell damage, and it applies no
on-hit or on-attack effects of items or runes (it doesn't use Spellblade). What the kit's own buffs
add to it (an empowered attack) and its hooks still apply.

**A step that is an empowered attack** (Zeri's P, her fully charged attack): `attack: true` on the
ability makes its step the champion's attack, waiting for the attack timer and restarting it, with
the ability's `buff` (`empowerAttacks`) empowering it.

**On-hit vs on-attack.** The wiki's [Attack effects](https://wiki.leagueoflegends.com/en-us/Attack_effects)
page lists which abilities apply on-hit effects and which also trigger on-attack effects (with
reduced effectiveness where it applies); each ability's wiki data says the same ("applies on-hit
effects … and triggers on-attack effects"). Flag both: `onHit: true` alone means Spellblade and
other on-hit effects apply, but Guinsoo's/Lethal Tempo/Energize charges don't stack.
`npm run wiki && npm run audit` compares every kit with the wiki's ability descriptions.

**Pets**: `pet: true` components with `hits`/`interval` for the typical uptime in a trade; document it.

### More building blocks

* `dv.Effect5Amount` reads legacy effect amounts (`effects` arrays in inspect output).
* `castTime` (ability or variant) may be an expression, e.g. `'calc.TotalCastTime'`. The data's cast
  times are the wiki's (none for instant casts like Garen Q, Darius W, dashes), else the game files'.
* Timing: a hit lands `castTime + delay + travel` after the cast starts. The target stands at
  `distance`: your attack range as the combo starts (edge to edge), unless the `distance` option
  places it. `reach` is how far an ability goes to it: `distance`, or its range if that's shorter.
  Travel is that at its missile's (or dash's) speed, the wiki's: expressions read `reach`,
  `castRange`, `missileSpeed` and `castTime` (the cast's own, the kit's when it sets one; `Q.reach`,
  `spell['X'].missileSpeed` read the data). A dash to the target is busy for its flight
  (`lockout: 'castTime + reach / missileSpeed'`); one of a set length (Vayne Q), or not at the
  target, takes its range; without a speed in the data it keeps a rough duration. A missile the
  wiki fires as the cast time starts flies `'reach / missileSpeed - castTime'` (a close target is hit
  before the cast time ends); an effect applied before then takes a negative delay (down to
  `'-castTime'`, Riven W). A
  returning missile flies out its range and passes the target on the way back (Ahri Q, Sivir Q):
  `castRange / speed + (castRange - reach) / backSpeed`.
* `windup` is an attack's windup at the current attack speed, for casts the wiki times by it
  (`castTime: '0.8 * windup'`, Senna Q). Hooks see a cast's cast time as `cast.castTime`.
* `cc: [{ kind, duration, delay }]`: `delay` lands the CC later (delayed stuns); a duration ≤ 0 means no CC,
  so `duration: 'debuff.flux ? dv.RootDuration : 0'` makes it conditional.
* `empowerAttacks.onHitRepeats`: extra on-hit applications per empowered attack (Renekton W).
* Marks: `armorReductionPerStack` / `mrReductionPerStack` (fractions) shred while stacked.
* Charges (ammo) come from the data automatically (`mMaxAmmo`/`mAmmoRechargeTime`): Rengar, Caitlyn W, Teemo R…
* Hooks can call `sim.setMarkStacks(id, n, duration?)` and `sim.setMarkCooldown(id, seconds)`.
* `recast` in expressions = 1-based index within a recast chain (Riven Q1/Q2/Q3, Aatrox Q); `recastWindow` ends the chain (full cooldown from the first cast).
* `onHitEffectiveness` also works on an empowered attack's components (Azir soldier stabs).
* `lockout`: seconds the caster is busy from cast start (channels/dashes) without delaying damage;
  `variableDuration: true` when the player can end it early (see Components). Ended early, a cast's
  `attackLockout` and `castLockout` end with it too.
* `attackLockout`: seconds from cast start the caster can't attack but can still cast, as in a dash the
  wiki allows casting during (Fizz Q, Jax Q, Sett E). "Unable to act" stops casting too: that is
  `lockout`, as it is when the only cast left readies an attack that waits anyway (Blitzcrank Q: Power
  Fist). Attack resets don't end it: Fizz's "Q W AA" casts W at once, and its empowered attack waits
  for the dash.
  Hooks lock attacks with `sim.lockAttacks(until)` (Jhin's reload) and reset them with `sim.resetAttack()`.
* `castLockout`: seconds from cast start the caster can't cast abilities but can still attack: one
  expression for all of them (Aurora R), or per slot, `{ E: 0.5 }` (Fizz Q). Hooks call
  `sim.lockCasts(['Q', 'E'], until)` (Renekton after his empowered W attack).
* `cooldown`: base cooldown expression when the data's is missing/wrong; `notUltimate: true` for an R that isn't one (Udyr).
* `buff` may be an array (several buffs per cast).
* `followUpCrits: true`: the cast sets off a hit that can crit outside its components (a hook's;
  Viego R's second strike), so crit marks (`R!`, the web's crit buttons) apply to it.
* `empowerAttacks.cc`: CC when the empowered attack lands (TF Gold Card); empowered components honour `delay`/`interval`.
* `onHitEffectiveness` on attack/onHit components scales item on-hit damage (Azir soldiers 0.5).
* `source` on a component sets the displayed source name (e.g. Varus W on-hit "Blighted Quiver").
* Marks: `atMax.debuff` / `atMax.cc`.
* Multi-hit `attack: true` components are separate attacks per hit (Electrocute counts each) unless `sameCast: true`.
* Variants inherit the ability's buff/debuff/cc/castTime unless they set their own (`cc: []` clears).
* `recastWindowFrom: 'previous'` measures `recastWindow` from the previous cast (Aatrox Q).
* Buffs: `bonusArmorPenPercent` / `bonusMagicPenPercent`. Stats: `critChanceMult: [2]` (Yasuo passive).
* `penPercent` on a component: extra % armor/MR penetration for that hit only (Gangplank barrels 0.4).
* `target.immobilized`, `target.slowed`, `target.impaired`, `target.cced` (1/0) for CC-dependent effects.
* Optional components in buffs/empowered attacks are enabled per attack: combo `AA+bounce`.
* Mark components (onStack/dot/atMax) honour `delay`/`interval`.
* Cooldown resets/refunds from hooks work: casts process pending events before checking cooldowns.
* Hooks run inside `deal()`, before the cast's own debuff and CC are applied (use `sim.schedule(0, …)` to defer).

## Hooks (last resort)

For mechanics the declarative format can't express, `hooks` accepts the same hook interface items and
runes use (`src/engine/effects.ts`): `onCast(sim, cast)`, `onAttack(sim, atk)`, `beforeDamage(sim, inst)`,
`afterDamage(sim, inst)`, `dynamicStats(sim)`, `onStart(sim)`, `onCrit(sim, inst)` (an item made the
hit a crit: Shadowflame's Cinderbloom; Yunara's passive amps it). A champion's damage the game deals
as an amp on another hit can be shown as a hit of its own, under its source: a `multiplier` with a
`hit` name (and an `id`); item and rune amps stay in the hit. A ranged attack is launched at the end
of its windup and hits when its missile arrives, flying from attack range at most (a form that attacks in melee sets `attack.melee`, an expression:
Elise's `'buff.eliseSpiderForm'`, and hits at once):
`onLaunch(sim, launch)` runs at the launch, for what
happens on-attack (Lucian's double shot, Kalista's Soul-Marked), `preAttack`/`onAttack` at the hit,
for what it does on-hit; what kit buffs add to it (`onHit`, `empowerAttacks`) is decided at the launch.
`sim.launchAttack({ castId, amount, label })` fires an extra shot (Lucian's second). Useful Sim API: `sim.deal(request)`,
`sim.schedule(delay, fn)`, `sim.counter(key)`/`setCounter`, `sim.evalExpr(expr, { slot: 'Q' })`,
`sim.target`, `sim.stats`, `sim.time`, `sim.opt`, `sim.applyCC(kind, duration, castId)`,
`sim.isReady(key)`/`startCooldown(key, s)`. Keep hooks small and comment why they're needed.
